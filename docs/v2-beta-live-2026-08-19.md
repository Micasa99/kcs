## Resource与network事实

Kubernetes namespace硬限制为8 CPU、32 GiB、1 NVIDIA GPU。Beta API常驻占用250m CPU与
256 MiB，因此ResearchCosmos Test对WorkPackage暴露的effective ceiling为7500m CPU、32256 MiB、
1 GPU。native runner的CPU/memory/storage request与limit使用exact值；control sidecar的额外资源
单独计算，不再把8/32 runner渲染成16/64。

每个managed Attempt在Job创建前先创建deterministic NetworkPolicy。dynamic policy允许DNS、明确
gateway和必要control ingress；静态native gateway policy只允许到Traefik内部端口。observed policy
attestation证明对象identity/spec，不替代CNI dataplane证明。

最终canary的CPU与GPU Work Pod都通过私有gateway获得真实模型响应；GPU Pod看到exactly one RTX 4090。
launcher以non-root child启动Pi，并把`SSL_CERT_FILE`与`NODE_EXTRA_CA_CERTS`传入child。此前
`Connection error`被精确定位为child没有继承平台CA，而不是token、模型provider或放宽NetworkPolicy的理由。

## 当前不可重复发布的原因

1. `scripts/deploy_v2_beta.sh`的render allowlist仍拒绝`kube-system`，但当前bootstrap包含必须指向
   kube-system Traefik的`kcs-v2-beta-native-gateway-internal-egress`；对象计数和allowlist也漏掉该policy。
2. live API image的OCI revision标为`1a6db4a…`，容器内关键source bytes却包含后续`6fd0220`等修复并
   与HEAD一致。功能可核验，但该label不能作为clean source provenance。
3. 部署证书门禁未检查实际逻辑TLS authority `kcs-beta.ai-cosmos.cn`；live证书当前包含该SAN，脚本不能
   保证下一次仍满足。
4. API历史ReplicaSet存在，但没有完整change-cause；runtime ConfigMap原位更新，没有完整current/previous
   bundle manifest或PVC snapshot/restore演练。
5. 三个tunnel/relay systemd adapter尚未进入同一可恢复release manifest。

在这些项关闭前，不得把当前canary提升为可重复Beta release或Stable promotion evidence。
